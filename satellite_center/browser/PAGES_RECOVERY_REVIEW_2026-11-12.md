### Cache / offline correctness to verify

**Confirmed genuine prior source defect:** #95's worker `satellite-sw.js` used cache-first and keyed cached JS/CSS only by pathname, discarding `?v=`. Consequently a future `browser.js?v=new` could receive the old cached `browser.js?v=old` even while online; required modules missing from its precache were silently ignored during SW install. This separate PR replaces it with a **new cache version v2**, network-first with `cache:"reload"` for only the audited same-origin app assets, exact-path cache fallback **only on network failure**, HTTP 404 visible, atomic required ESM/HTML/CSS precache, and distinct optional mapping/icon assets. Release version and both `browser.css?v=...` page references are bumped; any further source edits before publication require a **new cache version and URL review**.

Do not cache RF `.cu8`, WAV, IQ, BIN, ZIP, uploaded images, private outputs, `/api/`, third-party OSM/CelesTrak/NASA/CDN requests or external SDR services. Even after a successful offline install, `@jtarrio/webrtlsdr@3.0.7` and `satellite.js@6.0.1` load from a remote `esm.sh` CDN and are **not included in SW shell cache**; fresh TLE data and OSM tiles are also online. PWA first offline use, imported modules, icons, local Natural Earth fallback and browser back-button navigation must be tested under a registered service worker in an isolated HTTPS project-path preview. Never auto-refresh a tab performing WebUSB RF capture; release owned USB first and advise controlled reload after a version update. A browser crash cannot guarantee device cleanup.

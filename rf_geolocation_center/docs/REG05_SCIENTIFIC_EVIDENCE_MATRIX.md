## Status vocabulary

- **CODED / SYNTHETIC TESTED:** source functionality exists and can be exercised by mock data; not experimentally established precision or authentic RF reception.
- **EXTERNALLY ASSERTED:** accepts user/OS/catalog metadata, not independently verified by this application.
- **HEURISTIC:** computational model with unvalidated physical assumptions; **no statistical confidence coverage**.
- **UNIMPLEMENTED:** cannot perform stated measurement/fix with the current code.
- **HARDWARE NOT VERIFIED:** no real antenna, calibrated RF source, independent timestamped receiver array, ground-truth receiver location or multi-platform physical measurement.

All regression tests in this phase must be generated, clearly labeled **SYNTHETIC**. They demonstrate refusal/labeling/geometry only, never RF reception, accuracy, or model calibration.

### Source-specific gaps requiring correction in separately authorized implementation PRs

1. **Position selector parity:** Enforce the same finite WGS84 coordinates, timestamp parsing, **0 ≤ age < freshness bound**, provenance and identity checks in \`web/app.mjs:source()\`, \`core/source_provenance.mjs\` and \`core/location_layers.mjs\` rather than relying only on downstream sanitized entrypoints. Avoid treating a future clock skew as a fresh live fix. Historical NMEA file import must remain historical, not a current receiver observation.
2. **Raw I/Q evidence integrity:** \`web/rf_survey.mjs:acceptCapture\` accepts a browser event matching \`hardwareId\`, frequency, gain, bytes and source ID. Those fields can be emitted by other scripts; they are **not proof of a real authorized WebUSB capture**. Add an ownership-attested in-process measurement channel, timestamp sanity and source binding before promoting \`hasActualRF\`. Record device/driver identifiers with privacy and permission constraints; do not log secrets.
3. **Ranging independence:** Imported \`measured:true\` / \`synchronized:true\` flags currently encode assertions, not authenticated metrology. Require independently documented station locations, nonduplicate receiver IDs, source measurement method, clock domain, raw-sample lineage, independent ranges and times with quality flags, geodetic height/datum and station geometry before scientific promotion.
4. **RSSI calibration and coverage:** Require known-source identity, propagation/site and antenna records, repeated samples with calibration holdout, gain/temperature/power and bandwidth provenance, terrain/multipath conditions, and observed residual distribution. Fit/validate a physics-informed loss model. Never silently reinterpret ±3× sensitivity bands as 95% confidence.
5. **TDOA**: Real multi-station coherent capture and clock correction needed before any TDOA location. \`tdoaConstraints\` only checks a supplied boolean and scalar delta; it cannot establish synchronization, timestamp uncertainty or station independence.
6. **Gaussian/PSF**: Only after empirically grounded noise+clock/range covariance and geometry validation, calculate an uncertainty ellipse/distribution, confidence coverage against held-out ground truth, detect multimodality/outliers, and make the model type/data provenance visible. If unsupported, return \`confidence:null\` / “UNVERIFIED”, **not zero**.
7. **Flight interface**: Resolve REG-04 in Flight owner's workstream; specify independent ICAO count (3 vs 4), LIVE/BEST/history semantics, antenna vs Internet authenticated reception flags, station velocity/time, and safe shared-device lease. **Do not implement in this RF Geo PR**.
8. **No GPS from strong signal:** A strong 1575.42 MHz I/Q energy reading is not a decoded GNSS PRN, C/N0, pseudorange, navigation message, clock bias, PVT, or position; a strong 98.6 MHz peak does not authenticate its OSM tower.

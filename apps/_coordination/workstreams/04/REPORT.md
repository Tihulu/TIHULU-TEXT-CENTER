## Scientific honesty and safety findings

1. **Real input provenance:** `core/positioning.mjs` parses checksum-validated NMEA and experimental measured 2D ranges; `tdoaConstraints()` explicitly returns `positionFix:false`. `core/gnss.mjs` supplies geometry/orbit metadata, **not** a GNSS-SDR navigation fix. Browser location cannot prove GPS-only/non-GNSS positioning.
2. **RF ranging:** `core/rf_ranging.mjs` calculates raw I/Q relative power and permits a fixed-station calibrated RSSI *hypothesis*; it rejects moving aircraft/satellite references in the fixed-station 2D fit. RMS residual and the factor-three range sensitivity band are not covariance or measured position accuracy. Three aircraft position reports alone never yield this receiver's location.
3. **Ring semantics:** `web/app.mjs` distinguishes imported measured range circles, simulated explanation circles, RF model sensitivity circles and browser accuracy rings. That is **not** evidence for distinct per-aircraft *coverage*, Location, LIVE Fit and BEST Fit ring families. Source list and legends must not elevate references to measurements.
4. **RF On/Off discrepancy (P0 investigation):** `web/rf_survey.mjs` `setRfOnly(enabled)` calls `compute()` regardless of the flag, and initializes with `compute()`. Switching OFF does not call the WebUSB `release()` function. The separate Hard Stop button *does* call `release()` in `web/usb_sdr.mjs`. This is a source-based gap in the requested RF Off computation/ownership semantics; no running app was touched or functional failure measured.
5. **Performance:** fixed 96-point ring renderings, a 500-position volatile history limit, 60 source records and 72-tile guard are visible. No measured large-circle frame budget, spatial index or incremental fit acceptance is established.
6. **Platforms/language:** `index.html` uses `lang="en"` and visibly hardcoded English interface text. Do not infer EN/TR/DE coverage. PWA provides an offline coordinate grid, **not** a complete cached offline map. `native.py` is a localhost source launcher (with opt-in DVB bridge), **not** a GNSS SDR decoder or signed native installer. Linux, Windows, macOS, Raspberry Pi and mobile hardware acceptance remain pending. This is especially relevant to the native-desktop/no-WebUSB preference.

### Unresolved scientific inputs (REG-05 stays OPEN)

A real TDOA/MLAT claim would require **independent receiver-site coordinates (not independent aircraft IDs)**; hardware capture timestamps traceable to a common calibrated clock/UTC epoch with uncertainty; identical identified transmissions per site; controlled path delays; sufficient non-degenerate 2D/3D geometry; bounded stale/invalid observations; explicit measurement covariance and calibrated confidence-coverage validation. None follows from ADS-B positions alone, fixed broadcast tower catalogs, one RTL-SDR, RF signal strength, NMEA import, an illustrative radio-horizon intersection or Gaussian sigma slider. In standard receiver-site MLAT, multiple sites often locate an *aircraft* by arrival-time differences, so solving an *unknown receiver* site is a different inverse problem and must be specified and validated rather than assumed.

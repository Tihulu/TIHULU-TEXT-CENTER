### P0 exact strict-XFAIL oracle and its limits

PR #14 [L35–L44](https://github.com/Tihulu/tihulu-flight-radar/blob/b6a7510466efd5978b1724b5ce88830c1ecf9d71/tests/test_stage3_isolated_receiver_ownership.py#L35-L44) marks `test_external_readsb_should_survive_exit_release_opt_in` with `@pytest.mark.xfail(strict=True)`: with both services pre-existing and `_service_started_by_app=False`, `close(release_local_service=True)` should perform **no** stop. Moreover, this XFAIL lacks a `raises=`/exception-kind constraint: *any exception* can be XFAIL; this is material because old [PR #7's `close(self)`](https://github.com/Tihulu/tihulu-flight-radar/blob/4ef8245b87fc78cec6cc4f5f9043d68e08cf45d3/tihulu_flight_radar/control.py#L240-L259) does not accept `release_local_service`, so running this same test unchanged against #7 would produce an unrelated `TypeError` XFAIL instead of validating its ownership fix. Any future production fix needs an explicit new test-only review step that removes or narrows XFAIL after success; **XPASS(strict)** would itself fail CI until that is handled.

The canonical [`test_control.py` L72–L82](https://github.com/Tihulu/tihulu-flight-radar/blob/059b391280635d9aa4d2ac73c7318af9e135ebf5/tests/test_control.py#L72-L82) positively asserts existing paired Stop on Exit ON; that **older positive fixture conflicts with the target external-ownership invariant**.
